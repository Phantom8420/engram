Now, someone leaves, what if

The same graph answers three questions. Every answer comes with the path through the graph it rests on, so you can check it.

01 · NOW

Who really knows it

Knowledge that fades over time, not just a list of who touched the file once. Who owns a module versus who knows it, why the code is the way it is, which docs have fallen behind, who should take a new issue.

02 · SOMEONE LEAVES

The exit interview

A loss meter for the important knowledge nobody wrote down. Questions are ranked by how much of that loss each answer recovers. Answers go back into the graph, and the meter drops.

Run an interview →
03 · WHAT IF

Fork the graph

GRAPH.COPY makes a throwaway fork. Remove a person or reverse a decision there, rerun the same queries and diff the results: code left with nobody to ask, docs to rewrite, decisions built on the old one.

Try a scenario →

Does it predict anything?

Each test forks the graph, deletes everything after a cut-off date, works out who knew what on that day, and checks the prediction against what actually happened next.

Not every test is a win, and the losses are shown too. Over the last year, picking "the three busiest people" predicts the next author better (77% against 31%), because one contributor ramped up fast through CI and docs work.

The graph does the work

No vector store with a graph drawn on top. Every answer is a fixed, parameterised Cypher query. Nothing a user types is turned into Cypher.

Temporal edges

Every edge carries its own dates. KNOWS scores fade, halving after about eight months away from the code.

sum(weight * exp(-toFloat($asof - pr.created_at) / $decay))
GRAPH.COPY forks

What-ifs and backtests run on a copy of the graph that is deleted afterwards. The live graph is never written to.

g.copy("fork_…") MATCH (:Person {handle:$h})-[k:KNOWS]->() DELETE k
algo.pageRank

PageRank over co-changes finds the code everything else depends on. That code is weighted most in the loss meter.

CALL algo.pageRank('Module', 'CO_CHANGES')
Decision lineage

Decisions link to the PR they were made in, with verbatim quotes, the code they affect and the decisions they replace.

(Decision)-[:DECIDED_IN]->(PR) (Decision)-[:SUPERSEDES]->(Decision)
